# 涨停题材页规则

> 路由标识：`hotboard`。本文件仅覆盖涨停题材页；未声明部分继承 `../MASTER.md`。

## 用户任务与信息顺序

1. 先确认数据日期、采集时点与整体可用性，避免把旧快照误认成实时盘面。
2. 用服务端返回的题材聚合结果回答当前涨停集中在哪些题材；前端不重算题材强弱或交易结论。
3. 唯一主动作是刷新本页数据；题材名称只在存在真实目标地址时使用链接，否则保持文本。
4. 在题材摘要之后展示关联涨停股明细、证据状态和缺失/降级说明。

## 页面结构

- 标题区：页面标题，以及合并后的数据日期、采集时点、整体状态和覆盖说明；刷新复用应用顶栏动作。
- 状态区：加载、真实空数组、局部失败、陈旧数据分别呈现，不互相替代。
- 题材列表：按接口原始顺序展示题材名称、涨停家数和关联股票；不得在浏览器生成评分或排名。
- 数据治理：展示来源、覆盖/质量状态、缺失字段说明和“仅供决策支持”边界。

## 组件与交互

- 顶部刷新采用页面模块级更新：仅重新请求涨停题材接口并更新本页响应式状态，不连带刷新决策概览，也不执行浏览器整页重载。

- 题材卡使用 1px 边框、8px 圆角、无阴影；数字使用等宽字体和 `tabular-nums`。
- 刷新必须使用原生 `<button>`，最小触控区域 44×44px，并阻止重复提交。
- 宽明细在移动端转换为堆叠行；只有明细容器可横向滚动，且容器必须可键盘聚焦并有可读标签。
- 回封作为名称后的紧凑文字徽标；股票名称与代码保持同行。现价、几天几板、封板率、封单额四个排序表头使用明确边框、底色和排序状态。
- 表格正文提高字号、字重与行间留白；首板、二板、三板及以上使用不同色阶并始终保留板数文字，不能仅靠颜色区分。
- 请求失败只影响本页题材数据；保留页面标题、治理说明和重试入口。

## 响应式与无障碍

- 低于 720px 采用单列阅读顺序，正文基准 18px；不得通过缩小字体塞入桌面表格。
- 页面根节点使用 `min-width: 0` 与可换行布局防止页面级横向滚动。
- 状态反馈使用 `aria-live="polite"`；加载状态使用 `aria-busy`。
- 所有可见交互目标至少 44×44px，`:focus-visible` 使用 3px 高对比焦点环。
- 深浅主题均满足 WCAG 2.1 AA；上涨色只表达行情事实，数据质量同时使用文字说明。
- `prefers-reduced-motion: reduce` 时移除非必要过渡。

## 数据真实性

- `null`/字段缺失显示“—”并附“数据缺失”；真实空数组显示“当前无涨停题材数据”。
- `missing` 显示“数据缺失”，`degraded` 显示“数据降级”，接口失败显示“暂不可用”。
- 不以 `0` 代替缺失值；只有接口明确返回数值 `0` 时才显示 0。
- fixture 仅允许存在于 `frontend-vue/scripts/audit-ui.mjs`，生产组件不得内置示例题材或股票。
