# 资金择时页规则

> 本页覆盖 `MASTER.md`，仅定义资金择时的内容顺序、状态语义与响应式行为；未覆盖项继续遵循全局规则。

## 用户任务与信息顺序

1. 标题区同时给出数据日期、关键时点、整体质量状态和刷新入口。
2. 首屏先展示服务端确定的市场温度、四区域结论与唯一主动作；前端不得根据分项自行重算结论。
3. 紧随其后展示仓位边界、禁止条件和结论适用范围；缺失边界显示 `—` 并说明原因。
4. 结构化证据按“市场温度因子 → 指数择时 → 个股查询”排列，避免把查询工具置于全局结论之前。
5. 页面末尾展示数据来源、完整性、新鲜度、降级原因和方法口径。

## 视觉与交互

- 结论卡使用 1px 边框、8px 圆角和无阴影表面；温度数字、仓位上限和关键百分比使用等宽数字。
- 风险等级必须同时显示等级文字；涨跌红绿只表达行情方向，不表达风险或可执行性。
- 页面只保留一个高强调主动作“刷新数据”；个股查询为次级执行动作，均使用原生 `<button>`。
- 指数代码、数据来源等可跳转内容才使用真实 `<a>`；不得用可点击 `<div>` 或伪造 ARIA 角色。
- 加载超过 300ms 使用保留尺寸的骨架；局部错误使用 `role="alert"`，刷新结果使用 `aria-live="polite"`。

## 数据与状态语义

- 页面复用 App 壳的 `GET /api/pulse`，只读取服务端 `command.today_action`、`position_cap`、`first_principle`、风险等级与定格时点；失败时仅降级执行边界。
- 市场证据读取 `GET /api/timing`；个股查询读取 `GET /api/timing?code=<6位代码>`，查询响应只更新个股区，不覆盖已经展示的市场证据。
- 生产页面只消费真实 API，不包含示例指数、股票、温度或资金数值。
- `null` / 字段缺失显示“暂无该项数据”；`missing` 显示“数据缺失”；`degraded` 显示“降级数据”并列出原因。
- 真实空数组显示“当前没有可展示记录”；网络或接口失败显示“该模块暂不可用”，不得互相替代。
- 陈旧数据继续展示最近真实值，但必须同时标明数据日期或采集时点与“已陈旧”。
- 任一请求失败只降级其所属卡片，不阻断其他证据和个股查询。
- 分数、四区域、仓位建议和操作边界均以服务端字段为准；前端仅格式化单位和文案。

## 响应式与无障碍

- 页面默认单列，`900px` 以上可将指数择时与温度因子排为双栏；首要结论始终在 DOM 和视觉顺序中优先。
- `375px` 下指标网格改为单列或双列短项；字段名和值允许换行，不缩小到 18px 移动正文以下。
- 宽表仅在自身带 `tabindex="0"` 的容器中横向滚动；移动端优先改为卡片/堆叠行，页面根不得横向滚动。
- 所有可见交互目标至少 44×44px，相邻目标间距至少 8px，`:focus-visible` 使用 3px 清晰焦点环。
- 状态不得仅以颜色表达；动态状态、错误和查询结果提供文字及合适的 live region。
- 200% 缩放下不固定内容高度，不使用遮挡正文的 sticky 侧栏；遵守 `prefers-reduced-motion`。

## 生命周期

- 全页刷新与个股查询使用不同的 `AbortController`，重复操作先取消同类旧请求。
- 页面卸载时取消全部请求、清除刷新定时器并移除 `visibilitychange` 监听。
- 使用 generation guard 阻止卸载或较旧响应继续修改状态；本页不创建 SSE 或 ECharts 时不得引入对应运行时。
- 自动刷新只在服务端确认交易日且 `market_session` 为 `intraday` 或 `tail` 时执行；不得用浏览器本地时间猜测交易阶段。
