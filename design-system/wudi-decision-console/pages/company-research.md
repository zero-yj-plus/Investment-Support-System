# 公司研究页面规则

> 继承 `../MASTER.md`。本页只服务单公司深度研究，不承载产业链、条件选股、问股或其他研究页面。

- Vue 路由：`#/research?tab=company`。
- 不采用技能检索返回的巨型 Hero、夸张字号和营销 CTA；这些建议与 `MASTER.md` 及本页高密度决策任务冲突。

## 用户任务与信息顺序

1. 输入并核验 A 股代码，确认公司身份与数据时点。
2. 首屏优先展示服务端给出的确定性交易边界、风险/仓位约束与唯一主动作；未生成报告时，主动作是“生成公司研究”。
3. 在正文前展示官方公告证据覆盖、缺失项、降级与陈旧状态，避免把模型解释当成官方事实。
4. 报告正文按安全 Vue 节点渲染；历史研究按 append-only 记录展示，不覆盖既有事实。
5. 页面末尾说明数据来源、版本、生成状态和治理边界。

## 业务边界

- 公司代码、名称、行情、价格、涨跌幅、估值与官方公告均只展示真实接口值；缺失显示 `—` 或明确“未取得”，不得补零。
- 价格单位为人民币元，涨跌幅为百分比，PE/PB 为倍数；接口未提供单位时不凭字段名猜测。
- 官方公告、交易所证据、模型研究正文和服务端确定性交易段必须分区展示，不互相冒充。
- `missing`、`degraded`、真实空数组、陈旧快照、请求失败和生成流不完整分别呈现。
- 生成、存入知识库等动作防重复提交；知识库存入只准确表示服务端已接受，不夸大为已审批或已送达。
- 本页不在浏览器重算风险、仓位、价格区间、评分或推荐结论。

## 真实接口

- `GET /api/status`：读取模型连接与 Agent 能力状态；失败不阻断结构化证据。
- `GET /api/stock/{code}/research-enrichment`：盘后一致预期、十大股东与 GPJY 封锁状态。
- `GET /api/disclosures/announcements?code=...&limit=6`：巨潮与所属交易所的公告核验结果。
- `GET /api/interactions/management?code=...&limit=6`：深交所互动易问答；非正式公告。
- `POST /api/chat`：用户主动生成时以 `mode=company` 请求 SSE；不完整流隔离。
- `POST /api/knowledge`：只保存完整正文；成功仅表示已写入，不能称为已审批或已送达。

## 布局与视觉

- 页面头部使用紧凑标题、用途说明和数据/生成时点，不使用 Hero。
- 查询区使用真实 `<form>`、可见 `<label>`、股票代码输入与单一主按钮；输入和按钮高度至少 44px。
- 已有研究时采用“结论与动作 → 风险/仓位与禁止条件 → 官方证据 → 报告正文 → 历史与治理”的顺序。
- 卡片统一 1px 边框、8px 圆角、无装饰性阴影；间距只使用 4/8px 体系。
- 数字使用等宽字体和 `tabular-nums`，字号大于对应标签；风险色与涨跌色分离并附文字。
- 正文不使用未经清洗的 `v-html`；外部公告链接使用真实 `<a>`，执行动作使用 `<button>`。

## 响应式与无障碍

- 默认单列；桌面可将结论/风险与证据摘要组成不超过两栏的主次布局，正文始终保持可读行宽。
- 低于 760px 时查询表单、动作组、证据指标和历史条目改为纵向堆叠；不通过缩小字体塞入桌面布局。
- 宽明细仅允许自身容器横向滚动并可键盘聚焦；优先在手机端转换为标签/值堆叠行。
- 页面级不得横向滚动；长代码、URL 和报告文本允许断行。
- 所有可见交互目标至少 44×44px，间距至少 8px；`:focus-visible` 使用清晰 3px 焦点环。
- 状态变化使用 `aria-live="polite"`，加载超过 300ms 才显示骨架或明确进度；支持 `prefers-reduced-motion`。
- 深浅主题正文对比度满足 WCAG 2.1 AA；颜色不得作为唯一状态线索。

## 状态要求

- 初始态：解释需要先核验股票代码，不显示任何示例公司或演示数字。
- 加载态：保留查询上下文，分区显示加载反馈。
- 无数据态：区分真实空公告、无历史、报告尚未生成和关键字段缺失。
- 局部失败态：公司/报告主流程、官方公告、历史/知识动作分别降级，单一接口失败不得拖垮全页。
- 陈旧态：显示真实数据日期或抓取时点，并明确“陈旧/缓存”，不得称为实时。

## 禁止项

- 不请求产业链、全市场筛选、持仓、观察池或其他页面接口。
- 不把报告中的模型判断提升为确定性交易结论。
- 不使用示例股票、默认数字、emoji、装饰性图标、巨型标题、渐变或玻璃拟态。
