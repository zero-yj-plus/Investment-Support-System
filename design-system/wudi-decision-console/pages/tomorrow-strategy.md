# 次日策略页面规则

本页继承 `../MASTER.md`，仅覆盖 `#/review?tab=tomorrow`。页面服务个人 A 股投资者，回答次日结论、当前动作、风险/仓位边界以及依据是否完整可靠。19:30 生成的策略只引用已经定稿的尾盘与收盘事实，不回写上游历史。

## 信息顺序

1. 标题、策略数据日期、19:30 生成时点。
2. 与今日复盘共用“收盘确定性结论”组件，先展示风险、动作边界、仓位边界和允许/禁止条件。
3. 明日观察池的价格触发条件，以及尾盘/收盘 lineage 健康。
4. 唯一正式次日策略报告、目录、版本与内容指纹。
5. 推送、数据治理和追加式留痕说明。

## 真实接口与单位

- `GET /api/reports/evening?date=YYYY-MM-DD`：读取正式报告。消费 `rtype`、`date`、`title`、`content_md`、`created_at`、`pushed`、`content_hash`、`report_version`、`plan_version`、`cockpit`、`input_lineage`、`claim_validation`、`advice_governance`。
- `GET /api/watchlist`：读取服务端观察池。`quote.price`、`target_low`、`target_high` 单位为人民币元；`quote.change_pct` 单位为百分比；评级、状态和目标区间不在浏览器中重算。
- 用户明确触发时才调用 `GET /api/status`、`POST /api/reports/evening/generate` 和 `POST /api/reports/evening/push`。
- `pushed=true` 只表示已经提交推送，不能表述为平台接受或已经送达。

## 缺失与降级

- `null` 或字段缺失展示为“缺失/未提供”，不得补 0。
- `items: []` 展示“真实空数组”，与接口失败分开。
- 报告和观察池使用独立 AbortController；任一接口失败只降级对应模块，已经加载的另一模块继续展示。
- 陈旧报价必须同时显示“陈旧”和报价时点；报告 `stale` 单独标识。
- Markdown 只能通过安全 Vue 节点解析；禁止未经清洗的 `v-html`。

## 交互与生命周期

- 收盘确定性结论的结构、缺失语义和响应式样式与今日复盘完全共用；次日页只把唯一主动作链接到观察池锚点。
- 生成与推送防重复提交；停止 SSE 后明确说明未完成内容不冒充正式定稿。
- 页面卸载时取消报告、观察池、生成和推送请求，清理观察池定时器和 `visibilitychange` 监听。
- 所有可见目标至少 44×44px，焦点遵循主设计系统；平滑滚动尊重 `prefers-reduced-motion`。

## 响应式

- 页头说明不设置固定最大宽度；桌面空间足够时保持单行，窄屏空间不足时自然换行。
- 1100px 以下结构化证据改为单列。
- 900px 以下报告目录取消 sticky 并进入正文流。
- 720px 以下结论、护栏与规则改为阅读优先单列。
- 520px 以下观察池字段完全堆叠；页面本身不得横向滚动。
- 宽表只在报告表格容器内滚动，并且容器可获得键盘焦点。

## 验收

- 路由可达且不触发与本页无关的重型业务接口。
- 加载、无定稿、真实空观察池、陈旧数据、报告失败和观察池失败均有独立状态。
- 深浅主题通过 WCAG 2.1 AA；375px 与 1440px 无页面级横向滚动和小于 44px 的可见交互目标。
- 生产组件无固定股票、示例价格或猜测交易结论；固定数据只存在于 UI 审计脚本。
