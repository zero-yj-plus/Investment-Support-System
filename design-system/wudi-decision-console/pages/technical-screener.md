# 技术面选股页面规则

> 本文件仅覆盖 Vue 技术面选股页；未声明部分继承 `../MASTER.md`。技术面选股与“条件选股”是两个独立页面，不共享业务结论或接口语义。

## 页面任务与信息顺序

1. 标题区先展示缓存数据日期、更新时间、覆盖状态和刷新入口；不得把本地缓存标成实时行情。
2. 首屏结论只回答当前缓存是否可筛、命中数量和唯一主动作“执行筛选”。候选是规则命中，不是推荐。
3. 风险边界明确说明：技术信号不等于买入建议，不提供仓位、价格区间或风险等级；这些结论必须进入服务端诊断链路取得。
4. 规则编辑器按“事件条件”和“状态条件”分组，保留 AND / OR 逻辑、周期、信号库和方案管理。
5. 结果区先显示服务端命中数与覆盖语义，再显示候选证据、信号日期和可跳转诊断链接。
6. 最后展示缓存版本、数据健康、缺失/降级原因和最近筛选历史。

## 数据与状态语义

- 生产页面只消费技术选股 API 返回的真实缓存、规则、方案和筛选结果，不包含示例股票、示例数字或浏览器生成的技术结论。
- `null` / `missing` 显示“— / 数据缺失”；真实空数组显示“当前规则无命中”；`degraded` 显示“缓存降级”及原因；请求失败显示局部“暂不可用”并保留其他区域。
- `refresh` 只表示显式提交重型缓存更新；必须区分“刷新已提交/正在刷新”“刷新完成”和“刷新失败”，不得把排队或接受表述为数据已经更新。
- 金额、价格、涨跌幅、技术值和日期按 API 契约原单位展示；不得以 0 补缺。
- 筛选、排序、信号解释和结果集合以服务端为准；前端只管理规则输入、当前返回行的可访问展示和跳转。

## 布局与组件

- 桌面采用 `minmax(300px, 0.78fr) minmax(0, 1.22fr)` 双栏：左侧规则工作区，右侧结果；低于 1024px 改为单列。
- 规则工作区拆分为缓存摘要、方案工具条、逻辑/周期控制、条件列表和主提交动作；每个字段使用真实 `label`。
- 结果桌面使用自身可聚焦的横向滚动容器；移动端改为候选卡片，不依靠缩小字体硬塞表格。
- 信号库使用可关闭的模态/抽屉，提供标题、搜索、分类、选择计数、取消与确认；打开时聚焦首个控件，关闭后归还触发按钮焦点。
- 卡片保持 1px 边框、8px 圆角、无阴影；数字使用等宽字体与 `tabular-nums`。

## 交互与无障碍

- 提交、刷新、方案保存/删除和加入观察池使用原生 `<button>`；诊断跳转使用真实 `<a>`。
- 所有可见交互目标至少 44×44px；键盘焦点环 3px，错误使用 `role="alert"`，动作反馈使用 `aria-live="polite"`。
- 防重复提交：筛选、刷新、方案写操作各自独立锁定；对应请求各自使用 `AbortController`。
- 页面卸载时中止所有在途请求、清理刷新轮询/延时器、`visibilitychange` 监听和任何焦点恢复任务；卸载后的响应不得改写状态。
- 支持 `prefers-reduced-motion`；颜色不得作为命中、缺失、降级或错误的唯一线索。

## 响应式与缩放

- 375px 与移动端按“缓存状态 → 执行筛选 → 规则 → 结果 → 数据治理”单列排序，正文基准 18px。
- 规则条件在移动端纵向堆叠，数值输入使用合适的 `inputmode`；固定操作区不得遮挡内容或系统安全区。
- 页面根节点禁止横向溢出；只有结果表自身可以横向滚动并允许键盘聚焦。
- 200% 缩放后不使用固定高度截断核心规则、结果或错误信息。

## 审计状态

审计 fixture 至少覆盖：加载中、真实空结果、缓存降级/陈旧、筛选接口局部失败，以及 375px 深色、1440px 深色和 1440px 浅色。fixture 仅存在于 `frontend-vue/scripts/audit-ui.mjs`。
