# 知识库页面规则

> 继承 `../MASTER.md`。本页只服务知识条目的检索、治理与追加式管理，不承载报告中心、研究生成或其他业务页面。

- Vue 路由：`#/history?tab=knowledge`。
- 不采用技能检索返回的 Bento 营销布局、巨型 Hero、夸张字号、Google Fonts 或装饰性滚动动画；这些建议与 `MASTER.md` 的高密度决策台、既有字体和低动效规则冲突。

## 用户任务与信息顺序

1. 用紧凑指标概括知识库当前规模、待审核规模、数据时点和治理边界，不重复展示治理标题或契约版本。
2. 唯一主动作是新增知识；搜索、分类和状态筛选是次级工具。
3. 待审核条目优先于已生效和已拒绝条目，审批、拒绝、替代与删除都必须准确表达服务端结果。
4. 条目卡片只展示记录时点与正文摘要；来源与版本关系仅在存在治理依据时渐进展开。
5. 页面末尾说明来源、版本、追加式语义和接口健康。

## 业务边界

- 条目、分类、标签、正文、来源、状态和时点只展示真实接口值；缺失显示 `—` 或明确“未提供”，不得补零或填入示例内容。
- `pending`、`approved`、`rejected`、`superseded` 等状态由服务端决定，前端不得依据字段存在与否自行推断。
- `missing`、`degraded`、真实空数组、陈旧数据、请求失败和动作失败分别呈现。
- 新增、审批、拒绝、替代和删除必须防重复提交；成功只表示相应 API 已接受并返回结果，不夸大为外部送达。
- 历史知识与治理操作遵守 append-only 语义；替代关系必须保留旧条目，不把历史事实原地改写。

## 真实接口与字段

- `GET /api/knowledge`：读取 `schema_version`、服务端状态 `summary`、`review_queue_count` 与 `items[]`。页面不额外请求报告、行情或研究接口。
- `POST /api/knowledge`：手工新增 `{category,title,content}`；当前服务端契约把明确用户录入直接记为 `approved + explicit_user_input`，页面不得称为待审草稿。
- `POST /api/knowledge/{id}/approve`：提交 `source_report_ids/evidence_ids/sample_count`；来源真实性、样本数与可批准状态均由服务端核验。
- `POST /api/knowledge/{id}/reject`：提交必填 `reason`。
- `POST /api/knowledge/{id}/supersede`：原子创建已批准新版本并保留旧版本替代关系。
- `DELETE /api/knowledge/{id}`：删除列表条目；成功只表示服务端已删除并追加审计事件，页面不声称可恢复。
- 条目关键字段：`id/rule_id/category/title/content/status/version/origin/source_report_ids/evidence_ids/sample_count/created_at/created_by`，以及审批、拒绝、替代时点与关联 ID。
- 本页无价格、涨跌幅、风险或仓位单位；`sample_count` 是样本条数，`version` 是版本序号，时间字段为服务端字符串。接口未提供独立 `data_date`、新鲜度或 `degraded` 字段，不得自行构造。

## 布局与视觉

- 页面头部使用紧凑标题、用途说明、条目计数与最新时点，不使用 Hero；宽屏条目区使用三列卡片以提升信息密度。
- 首屏采用“状态结论与主动作 → 待审核提醒 → 搜索/筛选”的顺序。
- 新增区使用真实 `<form>`、可见 `<label>` 和单一主按钮；执行动作使用 `<button>`，可跳转内容使用真实 `<a>`。
- 卡片统一 1px 边框、8px 圆角、无装饰性阴影；使用 4/8px 间距体系。
- 条目状态始终使用文字和结构标识，颜色仅作辅助；日期、计数和版本使用等宽数字与 `tabular-nums`。
- 正文通过安全 Vue 文本/节点渲染；禁止未经清洗的 `v-html`。

## 响应式与无障碍

- 默认单列；桌面可使用不超过两栏的“筛选侧栏 + 条目列表”，主列表宽度优先。
- 手机端筛选器、动作组和元数据改为纵向堆叠；条目正文允许断行，不通过缩小字体硬塞。
- 页面级不得横向滚动；若出现宽明细，只能在自身可聚焦容器内滚动。
- 所有可见交互目标至少 44×44px，相邻目标间距至少 8px；`:focus-visible` 使用清晰 3px 焦点环。
- 搜索使用原生输入，筛选使用原生按钮或表单控件；键盘顺序与视觉顺序一致。
- 加载与动作结果使用 `aria-live="polite"`；加载超过 300ms 才显示骨架或明确进度。
- 支持 `prefers-reduced-motion`；深浅主题正文对比度满足 WCAG 2.1 AA，颜色不得作为唯一状态线索。

## 状态要求

- 加载态：保留页面结构和筛选上下文，显示明确加载反馈。
- 无数据态：真实空数组显示“知识库暂无条目”，并提供新增知识主动作。
- 局部失败态：列表读取失败与单条治理动作失败分别呈现；单条失败不得清空已加载列表。
- 缺失态：字段缺失逐字段展示，不得转换为 0、空字符串或推断值。
- 陈旧/降级态：若接口提供日期、抓取时点或质量状态，必须原样标注，不得称为实时。

## 禁止项

- 不请求报告、行情、持仓、观察池、筛选或其他页面接口。
- 不在浏览器生成审批结论、可信度评分、风险等级或交易建议。
- 不把删除按钮伪装成普通链接，不使用 emoji、装饰性图标、巨型标题、渐变、玻璃拟态或营销 CTA。
